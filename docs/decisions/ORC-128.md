# ORC-128 — `claude -p` options: repository settings, web tools, session resumption

## Decision

**2026-10-22 — adopted by the dev: all the recommendations** on this page, those for the three needs as well as the overall one. It is also written in ticket ORC-128.

| Decided point | Option adopted |
|---|---|
| 1. WebFetch: disable it too? | **Kept.** Only WebSearch is disabled, via `deny` in the imposed settings. |
| 2. Add `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` as a defense? | **No.** `--setting-sources ""` is enough, and test no. 11 watches `CLAUDE.md` on every version. |
| 3. Telemetry: block it at the proxy or disable it with a variable? | **Both**: disabled with a variable, and blocked at the proxy as a defense. The variable is still to be measured in ORC-213. |
| 4. Session volume: the whole `CLAUDE_CONFIG_DIR` or only `projects/`? | **A whole `CLAUDE_CONFIG_DIR` per ticket**, with the token passed through the environment. |
| 5. Double the web tools `deny` with `--disallowedTools`? | **No.** The `deny` in the factory settings is enough. |

The claims marked "not verified" below remain so: the decision does not verify them.

> **Status: decided** (see above). The tickets that depend on it are ORC-205 and ORC-217 (blocked until this decision), then ORC-136, ORC-188, ORC-213 and ORC-215.
>
> Version measured: **Claude Code 2.1.306** (`claude --version`), on October 21, 2026. The MVP doc cited by the ticket is a claude.ai artifact that the session could not open. This page relies on the ticket, the linked tickets and real measurements.

## The question

The MVP doc sets three needs for the agent launched by the factory, without giving the exact options:

1. **Ignore all repository settings** (`.claude/settings.json`, `.claude/settings.local.json`, `CLAUDE.md`, `.mcp.json`, the repository's hooks, skills and plugins). Load only what the factory imposes.
2. **Disable the built-in web tools** (WebFetch, WebSearch) if they open a network path that the egress proxy does not see.
3. **Resume a ticket's session**, and know what breaks that resumption.

Starting point in Relais: `buildClaudeArgs` (`src/adapters/runner/claude-code.ts`) passes `--setting-sources project,local`, `--settings <run-settings.json>`, `--plugin-dir <pack>`, and `--session-id` or `--resume`. The pack (`packs/standard/settings.json`) puts neither WebFetch nor WebSearch in `allow`, nor in `deny`.

## Criteria

In the ticket's order, then those of the linked tickets:

- **C1. Nothing from the repository is loaded** as a setting. This is isolation test no. 11 of ORC-205: settings, memory, MCP, `.claude/`.
- **C2. What the factory imposes stays loaded**: `--settings`, the pack (`--plugin-dir`, with its hooks and skills), and the factory's MCP servers (`submit_result`, `ask`, then `kb_search`: ORC-188).
- **C3. No network path bypasses the egress proxy** (ORC-213).
- **C4. A ticket's session can be resumed** after a question, a review or a crash (ORC-217, ORC-220).
- **C5. Compatible with subscription accounts** (ORC-215: the only secret mounted is the OAuth token).
- **C6. Verifiable on every version**: an option that cannot be tested will be silently broken by an update.

On the factory side, next to the repository:

## Need 1 — Ignore the repository settings

### Available options (`claude --help`, 2.1.306)

| Option | What the help says | Verified here |
|---|---|---|
| `--setting-sources <sources>` | « Comma-separated list of setting sources to load (user, project, local) » | **yes** (calls 2, 3, 5, 11-13) |
| `--settings <file-or-json>` | additional settings | **yes** (calls 3, 5) |
| `--strict-mcp-config` | « Only use MCP servers from --mcp-config, ignoring all other MCP configurations » | **yes** (calls 3, 5, 11-13; call 8, without it, serves as control) |
| `--mcp-config <configs...>` | MCP servers from JSON files | **yes** (calls 3, 5) |
| `--plugin-dir <path>` | plugin for this session only | **yes** (call 5) |
| `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` (env var) | **absent from `--help`**; found in the binary (`strings … \| grep CLAUDE_CODE_`) | **not verified alone**: always combined with `--setting-sources ""` (calls 4, 5), which is already enough |
| `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` | absent from `--help`; found in the binary | **not verified** (passed to calls 4, 5, effect not observed) |
| `--bare` | ignores hooks, installed plugins, auto-memory, `CLAUDE.md` discovery, but « Anthropic auth is strictly ANTHROPIC_API_KEY or apiKeyHelper (OAuth and keychain are never read) » | **not verified** |
| `--safe-mode` | disables CLAUDE.md, skills, installed plugins, hooks, MCP… | **not verified** |
| `--restricted` | ignores user/project/local settings, but **removes Bash and the tools that execute code**, as well as WebFetch | **not verified** |

### What remains uncertain

- **Untested traps**:
  - plugins enabled by the repository (`enabledPlugins` or marketplace in `.claude/settings.json`);
  - `.claude/agents/`, `.claude/commands/`, output styles;
  - `CLAUDE.local.md`, `.claude/CLAUDE.md`, a parent directory's `CLAUDE.md`;
  - an `env` key in the repository settings.

  They are all **not verified**. Test no. 11 should add them to the fake repository.
- **`.mcp.json` with `--setting-sources ""` alone**: not verified. The calls that cut out `.mcp.json` all have `--strict-mcp-config` as well.
- **`AGENTS.md`**: it is not injected in any of the measured calls, even with the `project` source (call 13). We do not know in which case the built-in plugin `cc-plugin-agents-md` would load it. Not verified.
- **Managed settings (policy)**: the help for `--restricted` and `--safe-mode` says they always apply. The runner container has none. Not verified.
- **`--bare`** would cover `CLAUDE.md` with a documented option. But the help says it only reads `ANTHROPIC_API_KEY` or an `apiKeyHelper`, never OAuth: this is incompatible with the subscription accounts of ORC-215 (C5). Not tested, for lack of an API key on this workstation.
- **`--restricted`** removes Bash: unusable for `build`.

### Recommendation for need 1

```bash
claude -p … --setting-sources "" \
  --settings <run-settings.json> --plugin-dir <pack> \
  --strict-mcp-config --mcp-config <mcp-usine.json>
```

- **`--setting-sources ""`** instead of `project,local`. This is what cuts the injection of `CLAUDE.md` (call 13 versus call 11: same prompt, no tools, only the source changes), the hooks of `.claude/settings*.json` and the repository's skills.
- **`--strict-mcp-config` + `--mcp-config`**. Combined with empty sources, it cuts out `.mcp.json`. It also cuts out **the account's claude.ai connectors** (Drive, Docs, Canva…), which would otherwise be loaded in every run with a subscription account (ORC-215). Empty sources or not, only `--strict-mcp-config` removes them (calls 2 and 8).
- **`CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`**, as ORC-205 plans. Its effect is not verified.
- **No `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`** (point 2): it would duplicate the empty sources, but is not documented.
- **Keep the reset of `.claude/**`** planned by ORC-205, as defense in depth. The traps tested do not need it, but not every possible trap has been tested.

## Need 2 — Built-in web tools

### Do they go through the process's network?

**Call 6.** A local CONNECT proxy logs every host (`proxy.mjs`, 25 lines of Node). Claude Code receives it through `HTTPS_PROXY=http://127.0.0.1:18128`, with `--setting-sources "" --strict-mcp-config --allowedTools WebFetch WebSearch --max-turns 4`. We ask for a WebFetch of `https://example.com`, then a WebSearch.

```text
tool_use WebFetch  {"url":"https://example.com", …}   → « Le titre de cette page est « Example Domain ». »
tool_use WebSearch {"query":"IANA example domain RFC 2606"} → « Links: [{"title":".example","url":"https://en.wikipedia.org/wiki/.example"} … »

proxy.log:
15:37:13 CONNECT api.anthropic.com:443      (×8: model calls)
15:37:16 CONNECT example.com:443            ← WebFetch
15:37:16 CONNECT api.anthropic.com:443
15:37:22 CONNECT http-intake.logs.us5.datadoghq.com:443   ← telemetry
15:37:23 CONNECT api.anthropic.com:443
```

- **WebFetch** goes through the process's network, hence through `HTTPS_PROXY`. The proxy sees `example.com` in the CONNECT, so a filtering proxy could refuse it. The test proxy only logged: nothing was filtered.
- **WebSearch**: the proxy sees **no connection** to a search engine. The results arrive in the response from `api.anthropic.com`: the search runs at Anthropic. The proxy only sees `api.anthropic.com`, which it must allow for the agent to work. **This is a path it does not see**: it can neither filter nor log the domains visited. (Only traffic that follows `HTTPS_PROXY` was observed. Under `--network none` with the proxy as the only egress, there is no other path anyway.)
- **Telemetry (side finding)**: Claude Code sends telemetry to `http-intake.logs.us5.datadoghq.com`. ORC-213 must choose between blocking it at the proxy or disabling it.
- **`*_USE_CCR_PROXY` variables**: the binary contains `CLAUDE_CODE_WEBFETCH_USE_CCR_PROXY` and `CLAUDE_CODE_WEBSEARCH_USE_CCR_PROXY`. In some environments, WebFetch could therefore also go through Anthropic. They are not set on the runner. Not verified.

### How to remove them

Both ways remove the tools from the list announced to the model (`tools` of the `init` event):

- `permissions.deny: ["WebFetch","WebSearch"]` in the file passed to `--settings`: **verified** (calls 3 and 5: `web: []`);
- `--disallowedTools WebFetch WebSearch`: **verified** (call 4: `web: []`).

Without one of the two, the tools are present (calls 1, 2, 6). Call 6 allowed them via `--allowedTools`. What happens without an `allow` rule (refusal or permission prompt) was not measured: **not verified**.

### Recommendation for need 2

- **WebSearch: disable it**, via `deny` in the imposed settings. It bypasses the proxy (C3): this is the case the ticket's rule targets.
- **WebFetch: the ticket's rule does not ask to disable it**, since it goes through the proxy. ORC-213 even says the agent keeps "its fetch tool". Disabling it too would have gone beyond the measurements: it is kept (point 1).

Put the ban in the factory's `--settings` file rather than in `--disallowedTools`: it is the same place as the rest of the deny-list. It must be added to the ORC-205 deny-list, which today contains neither WebFetch nor WebSearch, and to its "one ban per entry" test, which is still to be written.

## Need 3 — Resume a ticket's session

### Options

- `--session-id <uuid>`: starts a session with this identifier. Already used on the first `dev` run.
- `-r, --resume <id>`: resumes the session. Already used when resumption is requested (`opts.resume`, or failing that `job.session === 'resume'`) **and** the ticket already has a `claudeSessionId`; otherwise a new identifier goes out as `--session-id` (`src/core/orchestrator.ts` l. 583-586).
- `--fork-session`: resumes in a copy, under a new identifier. Not needed: `review` already starts in a fresh session.
- `--no-session-persistence`: does not write a session. Not to be used for the implementer.

### Measurements

Session `22222222-…` was created in call 5 in `/tmp/orc128-Q9ZT/repo`. Its first answer is `INCONNU`. Its file is `~/.claude-perso/projects/-tmp-orc128-Q9ZT-repo/22222222-2222-4333-8444-555555555555.jsonl`, i.e. `$CLAUDE_CONFIG_DIR/projects/<encoded cwd>/<id>.jsonl`.

| Call | Change | Prompt | Result |
|---|---|---|---|
| 7 | `--resume 22222222-…`, same directory, same options as call 5 | « Qu'as-tu répondu à ma question précédente ? Recopie ta réponse exacte, en une ligne. » | **resumes**: `INCONNU`, its answer from call 5 |
| 8 | `--resume 22222222-…` from **another directory** (`/tmp/orc128-Q9ZT/autre`), `--setting-sources "" --tools ""` | « Qu'as-tu répondu à ma toute première question dans cette conversation ? Recopie-la mot pour mot, en une ligne ; si tu n'as aucun historique, dis AUCUN-HISTORIQUE. » | **resumes**: `INCONNU`, not `AUCUN-HISTORIQUE` |
| 9 | `--resume 22222222-…` with **another `CLAUDE_CONFIG_DIR`** (empty directory) | « Une ligne. » | **fails** before any API call: `No conversation found with session ID: 22222222-…` |
| 10 | `--session-id 22222222-…` on an **already existing** identifier | « Une ligne. » | **fails**: `Error: Session ID 22222222-… is already in use.` |

After call 8, the continuation is written to the **original file**, stored under the directory of the first launch. Its `cwd` goes from `…/repo` (18 lines, calls 5 and 7) to `…/autre` (9 lines, call 8):

```text
$ jq -r 'select(.cwd) | .cwd' ~/.claude-perso/projects/-tmp-orc128-Q9ZT-repo/22222222-….jsonl | uniq -c
     18 /tmp/orc128-Q9ZT/repo
      9 /tmp/orc128-Q9ZT/autre
```

Not verified:

- **Account change** (another OAuth token, same `CLAUDE_CONFIG_DIR`): the session file is local and does not carry the account, so resumption should work. There is no second account on this workstation to verify it.
- **System prompt on resumption**: the help for `--system-prompt-snapshot` (enabled by default) says that the system prompt of the first call is recorded, then sent back as is on every resumption, « even when a later launch passes different text ». A `CLAUDE.md` injected via `--append-system-prompt` (ORC-205) would therefore stay frozen at its value from the first run, until a compaction.
- **Resumption from another directory**: it works in 2.1.306 (call 8), but is not documented. Do not rely on it.

### Recommendation for need 3

- **Keep `--session-id` on the first run and `--resume` afterwards**, as today.
- **What breaks resumption is `CLAUDE_CONFIG_DIR`** (call 9), not the working directory (call 8). The ticket volume (ORC-217) must carry `$CLAUDE_CONFIG_DIR/projects/`, and each runner of the ticket must launch Claude with the same `CLAUDE_CONFIG_DIR`. Also keep the same worktree path from one runner to the next, since resumption from another directory is not documented.
- **`--session-id` on an existing identifier fails** (call 10). A first run relaunched after a crash (ORC-220) must switch to `--resume` as soon as the session file exists, or take a new identifier.

## Overall recommendation

Command line adopted:

- `<run-settings.json>` contains the ORC-205 deny-list, plus `WebSearch` (WebFetch is kept, point 1);
- `CLAUDE_CODE_OAUTH_TOKEN` carries the token, since the ticket's `CLAUDE_CONFIG_DIR` does not contain one (point 4). The variable name is not verified here (see ORC-215);
- the variable that disables telemetry (point 3) is not included: it is still to be chosen and measured in ORC-213;
- `--max-budget-usd` is the current option. Token and turn budgets replace it in ORC-136, ORC-215 and ORC-216.

```bash
CLAUDE_CONFIG_DIR=<ticket volume>/claude \
CLAUDE_CODE_OAUTH_TOKEN=<account token> \
CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 \
claude -p <prompt> --output-format stream-json --verbose \
  (--session-id <uuid> | --resume <uuid>) --model <model> \
  --setting-sources "" \
  --settings <run-settings.json> \
  --plugin-dir <pack> \
  --strict-mcp-config --mcp-config <mcp-usine.json> \
  --max-budget-usd <n> [--permission-mode plan]
```

Isolation test no. 11 (ORC-205) replays, on every Claude Code version, this page's booby-trapped fake repository, completed with the untested traps:

- **without tools** (`--tools ""`), so that the model cannot read `CLAUDE.md` or `AGENTS.md` as files;
- and, in a separate call **with** the `build` tools, checking that `WebSearch` is absent from the `init` event (under `--tools ""`, the list is always empty and the check would prove nothing).

- **ORC-215**:
  - `--bare` is excluded, since it ignores OAuth;
  - with `CLAUDE_CONFIG_DIR` on the ticket volume (point 4), the token arrives through the environment (`CLAUDE_CODE_OAUTH_TOKEN`, not verified here), not through a file in the config directory;
  - an account change between two runs of the same ticket is not verified.

## Decided points

The dev adopted the recommended option for each of the five points: see the table in the [Decision](#decision) section. The arguments weighed remain below.

1. **WebFetch: disable it too?** The measurements do not require it: it goes through the proxy. ORC-213 plans for the agent to keep its fetch tool. Disabling it would therefore go beyond the tickets' rule and contradict ORC-213. The argument for: one less surface, and a tool `build` can do without, since `curl` through the proxy does the same job. Option adopted: **keep it**, as ORC-213 plans, since the proxy sees it and can therefore filter it. Only WebSearch is disabled.
2. **Add `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` as a defense?** `--setting-sources ""` is enough for `CLAUDE.md` (call 13 versus call 11). The variable is not documented, and its effect alone has not been isolated. Option adopted: do not set it, and let test no. 11 watch `CLAUDE.md` on every version.
3. **Claude Code telemetry (`http-intake.logs.us5.datadoghq.com`): block it at the proxy or disable it with a variable?** Option adopted: disable it with a variable, and block it at the proxy as a defense. The candidate variables (`DISABLE_TELEMETRY`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`) are **not verified** here: to be measured in ORC-213.
4. **Session volume: the whole `CLAUDE_CONFIG_DIR` per ticket, or only `projects/`?** Option adopted: the whole `CLAUDE_CONFIG_DIR` per ticket, with the token through the environment. It is simpler to mount, and nothing from another ticket leaks.
5. **Double the web tools `deny` with `--disallowedTools`?** Option adopted: no, the `deny` in the factory settings is enough, once covered by the ORC-205 deny-list test.

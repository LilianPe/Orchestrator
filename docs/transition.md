# Transition: Relais's starting point

This page freezes the state of Relais from which the factory MVP starts, and states, for each module, what becomes of it and which ticket touches it. It serves as a reference for comparing and for rolling back; the target tickets keep it up to date (a ticket that removes or transforms a module updates its row).

## Working branch

The factory evolves from `main`, without a long-lived branch: each increment is an ORC ticket, on a branch named after it, and lands through a PR to `main`, never through a direct push to `main`. The `relais-v1-final` tag keeps the starting state.

## Data

No migration: `relais.db`, `transcripts/`, `workspaces/` and the knowledge repository start from scratch (ORC-178 archives and then deletes the old ones). Since ORC-167, the instance lives in `~/.factory` (database `factory.db`): nothing is read from `~/.relais`.

**Display name.** What a human reads (CLI help and messages, interface title and header, messages posted in Linear, password realm, name of the git identity of commits) comes from a single constant, `PRODUCT_NAME` in `src/product.ts`, currently `Orchestrator` (beta name). On the day of the final name, change this constant, the GitHub repository name and the docs; on an already configured instance, what was written under the old name does not follow and is renamed by hand: the Linear OAuth application, which `init` has created under this name and which is mentioned with @, and the title of the knowledge base's `INDEX.md`. The constant is read by:

- `src/cli/factory.ts`, `src/cli/init.ts`, `src/cli/factory-agent.ts` (help, questions and messages, title of the `INDEX.md` created by `init`);
- `src/app/bootstrap.ts` (daemon logs), `src/core/orchestrator.ts` (Linear messages), `src/server/app.ts` (HTTP Basic realm);
- `web/src/App.tsx` (header) and `web/vite.config.ts`, which replaces `%PRODUCT_NAME%` in the title of `web/index.html` at build time and in dev;
- the `Dockerfile`, which writes the image's git identity from `dist/src/product.js` after the build; `compose.yaml` passes `GIT_AUTHOR_NAME` and `GIT_COMMITTER_NAME` as is from the shell, without a default: when absent, they are not defined in the container and this name applies, `docker compose exec` included. The committer no longer reuses `GIT_AUTHOR_NAME`: define both for another name. Never define them empty (`GIT_AUTHOR_NAME=` in `.env` or the shell): the empty value passes as is and git then refuses every commit (« empty ident name »); remove the line to keep the image's name.

The pack texts (`packs/standard/`, skills and hook) cannot import the constant: they say "the factory", without a proper name.

**Remaining occurrences of `relais`.** In files tracked by git outside `docs/` and `README.md` (case-insensitive search), the lines below, checked by `src/product.test.ts`; transition lines carry the marker « transition, à retirer », which the test accepts:

## Module inventory

Starting statuses:

- **keep**: the module stays as is or nearly so; the cited ticket builds on it.
- **adapt**: the module stays, but the cited ticket transforms it.
- **remove**: the module disappears; the cited ticket replaces or removes it.
- **undecided**: no ticket clearly settles its fate (see the last section).

The first cited ticket is the one that touches the module first or the most; the following ones touch it too. `src/docs-transition.test.ts` checks that every non-test file of `src/` has a row, that every row (in `src/` or not) has one of the four statuses, that every cited path exists and is cited only once, and that the "Undecided" section lists exactly the rows with that status.
